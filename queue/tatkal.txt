Millions of people. One button. 10:00. | How does a ticket site survive a rush like that?

Using the Tatkal rush as the scenario (AC Tatkal opens at 10:00, one day before travel). This is how rushes like this are handled in general, not a claim about how IRCTC is built.

1. A waiting room: let in only as many people as the system can serve, everyone else waits in line
2. A cache: station lists and page files are the same for everyone, so serve them without the database
3. Limits per user: too many requests a second get slowed or blocked
4. The last seat: a database lock or atomic update lets exactly one request win, the seat is held a few minutes for payment, then released
