The intern could delete the database. | How AWS IAM decides who can do what

IAM (Identity and Access Management) answers three questions on every request: who is asking, to do what, on which thing.

How it works:
1. Rules are written as policies: Effect (Allow or Deny), Action (like s3:GetObject), Resource (which bucket)
2. Everything is denied by default. If no policy says yes, the answer is no
3. An explicit Deny always beats any Allow, which is how you build guard rails
4. Apps should use roles, which give temporary credentials, instead of secret keys pasted into code

Classic mistakes: a policy with "Action": "*" on "Resource": "*", and using the root user day to day. Root has full access, so protect it with MFA and use limited users or roles.
